# مشروع «حاسبة قياسات الشبابيك والواجهات»

ملف توثيق لاستكمال العمل لاحقاً. آخر تحديث: 2026-11-15 (أضيف: تبسيط التدفق إلى 3 خطوات، نافذة حفظ باسم المشروع، ملف PDF ملوّن، الكمية ونسخ الشباك السابق، نسخة احتياطية واستعادة. قبله: التقريب الاختياري لكل خانة. قبله: الواجهة الافتتاحية بتوقيع المبرمج، وصار التطبيق يفتح دائماً على اختيار النوع. قبلها: تعديل العلاقات، خانات وأنواع جديدة، القسمة، والعلاقة بخانتين).

## 1. ما هو المشروع؟
تطبيق ويب (ملف HTML واحد، يعمل بدون إنترنت) يحسب قياسات أجزاء الشبابيك والواجهات (الحصيرة، الصندوق، الزجاج، المنخل...) من **الطول** و**العرض** فقط، بنفس معادلات ملف الإكسل الأصلي، ويصدّر النتائج إلى ملف إكسل ملوّن. الواجهة بالعربية (RTL) ومصمّمة لمن لا يعرف الحاسوب. يمكن للمستخدم الآن تعديل العلاقات وإضافة خانات وأنواع جديدة بنفسه، وتبقى محفوظة.

الرابط المنشور (خاص بصاحب الحساب): https://claude.ai/artifact/Bm3d1stEVAez3qbhsTjJFh

## 2. محتويات مجلد المشروع
| الملف | وظيفته |
|---|---|
| `index.html` | التطبيق كله (واجهة + حسابات + تصدير إكسل). هذا هو المصدر الأساسي |
| `package.json` | يحدد مكتبات Capacitor (أندرويد، الملفات، المشاركة) |
| `capacitor.config.json` | اسم التطبيق `حاسبة الشبابيك` ومعرّفه `com.windowcalc.app` |
| `icon-only.png` / `icon-foreground.png` / `icon-background.png` | أيقونة التطبيق (نافذة بيضاء على خلفية زرقاء) |
| `.github/workflows/build-apk.yml` | وصفة GitHub لبناء ملف APK تلقائياً |

عند البناء تنسخ الوصفة `index.html` إلى `www/` والأيقونات إلى `assets/` ثم تنشئ مشروع أندرويد بـ `npx cap add android`.

## 3. خطوات استخدام التطبيق (3 خطوات)
بعد الواجهة الافتتاحية (القسم 3ب) يفتح التطبيق **دائماً على الخطوة 1 (النوع)** حتى لو كانت هناك قياسات محفوظة، وهي تبقى محفوظة وتظهر في الخطوة 2.
1. **النوع:** بطاقات الأنواع فقط (نظيفة). الضغط على بطاقة ينقل للقياسات. في الأسفل زر **«⚙ تعديل الأنواع والعلاقات»**: عند تفعيله يظهر تحت كل نوع زر «⚙ علاقات الخانات» ويظهر «＋ إضافة نوع جديد» (انظر القسم 4). والضغط على «✓ إنهاء تعديل الأنواع» يعيد الشاشة النظيفة. وفي الأسفل أيضاً قسم مطوي **«💾 نسخة احتياطية»** (القسم 4ب).
2. **القياسات:** سطر لكل شباك: الطول والعرض و**العدد** (اختياري، الافتراضي 1). تُضاف خانة جديدة تلقائياً. دائرة الرقم تسمح بتسمية الشباك. أدوات: **«⧉ نسخ الشباك السابق»**، لصق من إكسل، جرّب مثالاً، مسح الكل. زر «عرض النتائج» ينتقل مباشرة للنتائج.
3. **النتائج:** عرض بطاقات أو جدول ملوّن، وبطاقة «التقريب لكل النتائج» في أعلاها. الضغط على أي رقم ينسخه. زر **«⚙️ تخصيص الخانات»** يفتح شاشة التخصيص (كانت الخطوة 3 سابقاً)، وزر **«💾 حفظ ومشاركة»** في الشريط السفلي يفتح نافذة الحفظ (القسم 3ج).

### شاشة التخصيص (من زر «تخصيص الخانات»)
القياسان الأساسيان، ولكل خانة: مربع اختيار، علاقتها، نتيجتها الحية، حقلا زيادة ونقصان، وزرا «✎ تغيير» و«≈ تقريب». زر **«⚙ إعدادات متقدمة ▾»** يُظهر الأدوات النادرة: أزرار الترتيب ▲▼، خيار «تطبيق التعديل على الخانات المرتبطة»، «تصفير التعديلات»، «إرجاع العلاقات الأصلية»، «الترتيب الافتراضي». والمفتاح `advOpen` غير محفوظ (يُطوى عند كل فتح للتطبيق). الزر السفلي «تم» يرجع للنتائج.

### الكمية
حقل «العدد» في كل شباك (`r.q`). عند وجود عدد أكبر من 1 في أي شباك يظهر في البطاقات «×2»، وفي الملخص «3 شباك · 5 قطعة»، ويُضاف **عمود «العدد»** في الإكسل وPDF وCSV والنسخ (`last.xtable` و`last.xstruct`). الجدول والبطاقات على الشاشة لا يتغير ترتيب أعمدتها.

## 3ب. الواجهة الافتتاحية (Splash)
شاشة تعرض قبل الواجهة الأساسية وتحمل عبارة **«برمجة وتصميم المهندس يزن طشطوش»**. بألوان التطبيق (أزرق داكن، أبيض، ذهبي دافئ) وفكرتها هندسية تناسب مجال الشبابيك.

### التسلسل (نحو 6.8 ثانية)
1. خط ضوء يمسح الشاشة من الأعلى.
2. أضلاع إطار الشباك الأربعة تطير من الخارج بدوران وضبابية وتلتصق في أماكنها، مع **توهج ذهبي ناعم** حول الإطار وشرارات صغيرة وموجتين خفيفتين عند التجميع.
3. يُرسم الإطار الداخلي والصليب، ويظهر الزجاج بلمعانه ومقبضان ذهبيان.
4. خطوط القياس تتمدد والرقمان **120** (العرض) و**150** (الطول) يعدّان تصاعدياً.
5. تُرسم **لوحة العنوان الهندسية** (Title Block) بخطوط ذهبية، كما في المخططات: «حاسبة الشبابيك» في الأعلى، ثم «برمجة وتصميم»، ثم خانة الاسم.
6. يُدوَّن **«المهندس يزن طشطوش»** بنقطة ضوء تعمل كرأس قلم رسم تسير من اليمين لليسار، ثم يُرسم تحته خط قياس بسهمين وعلامة منتصف.
7. لمعة ضوء قطرية، ثم تكبير وتلاشٍ للدخول إلى التطبيق.

### السلوك
- **الضغط في أي مكان** يتخطى الواجهة فوراً. وتغلق نفسها تلقائياً بعد 6.8 ثانية (`setTimeout(close,6800)`).
- ميلان ثلاثي الأبعاد خفيف للشباك مع حركة الفأرة أو اللمس.
- تحترم `prefers-reduced-motion` (تقلّ الحركة ويُلغى الغبار والشرارات).
- تتكيف مع الشاشات الصغيرة (مثل 360×600): الأحجام بـ `clamp()` و`vh`/`vw`، ويختفي شريط التقدم على الشاشات الأقصر من 700px.

### أين هي في الكود
- **CSS:** كتلة تبدأ بالتعليق `/* SPLASH */` في آخر `<style>`، كل قواعدها تبدأ بـ `#splash`.
- **HTML:** `<div id="splash">` مباشرة بعد `<body>`، وفيه: `canvas#spc`، `svg#spw` (الشباك)، ولوحة العنوان `.tb`، وشريط التقدم `.bar`.
- **JS:** سكربت مستقل بعد عنصر `#splash` مباشرة: حلقة `canvas` (غبار وشرارات)، `burst()`، عدّاد الأرقام `cnt()`، ميلان الشباك، ودالة `close()` التي تضيف الصنف `out` وتزيل العنصر.
- **التوقيتات:** كلها في CSS عبر `animation-delay` (متغير `--d` في لوحة العنوان). لتغيير الإيقاع عدّل هذه القيم ومعها `setTimeout(close,6800)` ومدة `@keyframes bar`.
- لتغيير القياسين المعروضين غيّر النصين `120` و`150` ومعهما `cnt("n1",120,…)` و`cnt("n2",150,…)`.

### تنبيهات للتعديل
- **أسماء الأصناف:** لا تستخدم أسماء قصيرة عامة مثل `.v` أو `.h` أو `.res` أو `.rs` داخل الواجهة الافتتاحية، فقد تتعارض مع أصناف التطبيق نفسه (ظهرت بطاقات بيضاء وخطوط تحوّلت إلى كتل ذهبية). استعملت `hz` و`vt` و`tb`.
- **الحروف العربية:** لا تضف `letter-spacing` على نص عربي، فهو يقطع اتصال الحروف.
- **تنبيه CSS:** عند حذف سطر من كتلة `@media` تأكد أنها ما زالت مغلقة بـ `}`، فكتلة مفتوحة تبتلع كل القواعد بعدها وتجعلها تعمل على الشاشات القصيرة فقط.
- لم تُجرَّب الواجهة على جهاز أندرويد حقيقي، والاختبار كان في Chrome عبر Playwright.

## 3ج. الحفظ والمشاركة وملف PDF
زر «💾 حفظ ومشاركة» يفتح نافذة فيها:
- **اسم المشروع** (يدخله المستخدم يدوياً): يُكتب في ترويسة PDF وعنوان الإكسل، ويُسمّى به الملف (يُنظَّف من `\ / : * ? " < > |`). إذا تُرك فارغاً يُستخدم «نتائج_القياسات_التاريخ». يبقى الاسم محفوظاً أثناء فتح التطبيق (`pjName` غير مخزّن).
- **تلقائياً في الترويسة:** النوع والتاريخ وعدد الشبابيك (وعدد القطع إن وُجدت كمية).
- خيار **توقيع المبرمج** أسفل PDF («برمجة وتصميم المهندس يزن طشطوش») ومفعّل افتراضياً.
- أزرار: حفظ PDF، حفظ إكسل، مشاركة PDF، مشاركة إكسل. وتحت «خيارات أخرى»: نسخ للإكسل، إرسال كنص، CSV، وطرق بديلة.

### بنية ملف PDF
- A4 أفقي، **صفحات صور JPEG داخل PDF** بلا مكتبات: `buildPdf(info)` ترسم كل صفحة على `canvas` (الحروف العربية تُرسم بخط النظام) ثم `makePdfFromJpegs()` تكتب ملف PDF يدوياً (كائنات + xref).
- الترويسة (شريط داكن): اسم المشروع كبيراً، تحته النوع والتاريخ وعدد الشبابيك، وعلى اليسار اسم التطبيق ورقم الصفحة. وسطر ملاحظات صغير للتعديلات والتقريب.
- جدول بنفس ألوان الإكسل والنتائج (مجموعات ملونة وعناوين فرعية)، **تُكرَّر العناوين في كل صفحة**، نحو 19 صفاً في الصفحة.
- التذييل: التاريخ يساراً، والتوقيع (اختياري) يميناً.
- الأرقام هي المعروضة (مقرَّبة إن فُعّل التقريب).
- النص داخل الملف صورة، فلا يمكن تحديده. وحجم الصفحة نحو 200 إلى 350 كيلوبايت.
- التاريخ يُرسم مقطعاً مستقلاً بالاتجاه من اليسار لليمين لتفادي قلب الأرقام في السطر العربي.

## 4. تعديل العلاقات والخانات والأنواع
### محرر العلاقة (يظهر في الواجهة الأولى والخطوة 3)
ترتيب الحساب داخل العلاقة الواحدة:
1. **تُحسب من:** الطول أو العرض أو أي خانة تسبقها في الترتيب (لمنع الدوران).
2. **خانة ثانية (اختياري) + العملية:** جمع، طرح (الفرق)، ضرب (المساحة)، قسمة. القسمة على صفر تعطي 0.
3. **× أو ÷ رقم:** زر × يتحول إلى ÷.
4. **＋ أو － رقم.**

مثال المساحة بالمتر المربع: الطول × العرض ثم ÷ 10000. مثال الفرق: الطول － العرض.

### الواجهة الأولى: «⚙ تعديل الأنواع والعلاقات» ثم «⚙ علاقات الخانات»
تعرض خانات النوع مع نتيجة كل واحدة لمعاينة (أول شباك صحيح أو 120×150). كل تغيير يُحفظ فوراً. أزرار: «＋ إضافة خانة»، «↩︎ إرجاع كل العلاقات الأصلية» (للأنواع الأصلية فقط)، «✓ تم».

### خانة جديدة
«＋ إضافة خانة»: اسم الخانة، **مجموعة اختيارية** (مثل «الحصيرة» لخانتي طول وعرض؛ يوجد زر «＋ خانة أخرى في مجموعة …»)، ثم علاقتها. تظهر في الخطوة 3 والنتائج والإكسل بلون خاص. لا تُحذف خانة إذا كانت خانة أخرى تستخدمها كمصدر.

### نوع جديد
«＋ إضافة نوع جديد»: اسم النوع، ثم تُضاف خاناته وعلاقاته بنفس الطريقة. يمكن **إعادة تسميته** (حقل الاسم أعلى اللوحة) و**حذفه**. الأسماء الفارغة أو المكررة مرفوضة. الأنواع الأصلية الثلاثة لا تُعاد تسميتها ولا تُحذف.

### التقريب الاختياري (جديد)
داخل محرر العلاقة (في الواجهة الأولى وفي الخطوة 3) سطر **«التقريب»**: بدون، 0.1، 0.5، 1، ومعه **الاتجاه**: لأقرب، لأسفل، لأعلى (يتعطل الاتجاه عند «بدون»). الافتراضي «بدون»، فلا يتغير شيء لمن لا يستخدمه.
- **يؤثر على العرض والتصدير فقط:** الحساب الداخلي والارتباط بين الخانات يبقيان بالأرقام الأصلية، فلا تتراكم أخطاء التقريب. فإذا بُنيت خانة على خانة مقرَّبة تُحسب من القيمة الأصلية.
- **تقريب عام لكل النتائج:** في أعلى صفحة النتائج بطاقة «التقريب لكل النتائج» (بدون، 0.1، 0.5، 1 مع الاتجاه). يشمل كل الخانات ما عدا الثابت E، والخانة التي حددت لها تقريباً خاصاً تتبع تقريبها الخاص. «بدون» عند الخانة يعني أنها تتبع العام. يُحفظ في `S.gr = {s,d}` ضمن `winCalcV3`. وزر «≈ تقريب» الذهبي ظاهر بجانب «✎ تغيير» في كل خانة ويفتح المحرر مباشرة.
- **المعاينة:** تعرض الرقم المقرَّب مع «(الأصلي …)» في محرر العلاقة.
- **النتائج:** الرقم الكبير مقرَّب والأصلي صغير تحته (بطاقات وجدول). وإذا وُجد تقريب ظهر زر **«عرض الأرقام الأصلية»** أعلى النتائج يبدّل مؤقتاً (لا يُحفظ).
- **التصدير:** إكسل ونسخ وCSV ومشاركة النص تستخدم الأرقام المعروضة (المقرَّبة، أو الأصلية إذا فُعّل الزر).
- **التخزين:** `S.rnd[النوع][الخانة] = {s: الخطوة, d: n|d|u}` داخل المفتاح `winCalcV3`، وتُنقل عند إعادة تسمية النوع وتُحذف مع حذف النوع أو الخانة.
- **الكود:** `rndOwn()` (الخاص) و`rndCfg()` (الفعلي: الخاص ثم العام) و`rndApply()` و`shownV()` و`setRnd()` و`prevTxt()` قرب `relOv`، والأصناف CSS كلها تبدأ بـ `rn-`.

## 6. بنية الكود داخل index.html
- **المحرك** (`ENGINE-START`…`ENGINE-END`): `FIELDS`, `REL`, `ORDER`, `TYPES`, `compute()`, `fmt()`, `relText()`. تعديل وحيد على الأصل: `REL[k]` صار `[مصدر, ضرب, إضافة, مصدر2, عملية]` وتحسب `compute()` المصدرين ثم الضرب ثم الإضافة.
- **مصدّر الإكسل** (`XLSX-START`…`XLSX-END`): `buildXlsx()` و`makeZip()` بدون مكتبات.
- **الحالة `S`:** `type, rows, sel, inc, dec, rel, rnd, gr, raw, custom, cn, utypes, cascade, layout, view` (`raw` مؤقتة ولا تُحفظ).
  - `S.rel[النوع][الخانة] = {s, m, neg, a, dv, s2, op}` (المصدر، الضرب، إشارة الإضافة، الرقم، قسمة؟، مصدر ثانٍ، عملية `+ - * /`).
  - `S.custom[النوع] = [{id:"c1", name, group}]` الخانات الجديدة. علاقتها تُخزَّن في `S.rel` بنفس الشكل.
  - `S.utypes = [{name}]` الأنواع الجديدة.
- **`syncCustom()`**: تُستدعى من `applyRel()` وعند التحميل. تعيد بناء `ORDER` و`REL` و`LABEL` و`SUB` و`HUE` و`TYPES[..].fields` (مصفوفات) و`TN` و`TINFO` و`layout` حسب الخانات والأنواع الجديدة. معرّفات الخانات الجديدة `c<رقم>`، ووحدات المجموعات في `layout` بالشكل `cg:<النوع>:<المجموعة>` (`GN()` تستخرج الاسم للعرض). أسماء المستخدم تُنظَّف من `< > & "` عبر `clean()`.
- `applyRel()` تعيد `REL` إلى الأصل ثم تطبّق التعديلات، وتُستدعى في بداية `build()`. `DIV` يحفظ المقسوم عليه للعرض فقط.
- **الواجهة:** `go()`/`showStep()` مع `history.pushState`؛ `build()` يملأ `last`؛ `renderTypes/renderRelPanel/relEditor` للواجهة الأولى؛ `renderRows/renderFields/renderResults`.
- **البداية:** في آخر السكربت `load()` ثم `const start=1;` (كان `hadData?2:1`، وغُيّر ليفتح التطبيق دائماً على اختيار النوع).
- **الجديد (2026-11-15):** `openSave()`/`closeSave()` نافذة الحفظ، `exportXlsx()` و`exportPdf()`، `buildPdf()` و`makePdfFromJpegs()`، `backupData()` وزرّا النسخ الاحتياطي، `qOf()` للكمية، والمتغيرات `typeEdit` و`advOpen` و`pjName` و`noSave`. وأصناف CSS الجديدة: `svl` `svgrid` `svinfo` `svmore` `qx` `qb` `tmode` `noadv` `advonly`.
- **الحفظ `saveBlob()`**: صلاحية `downloads` في claude.ai ← إضافات Capacitor داخل أندرويد ← مشاركة الويب ← تنزيل عادي.

## 7. عمل ملف APK من الجوال خطوة بخطوة
لا يمكن بناء APK داخل Claude (لا يوجد Android SDK). الحل: خدمة GitHub Actions تبنيه مجاناً. كل الخطوات من جوال أندرويد بمتصفح Chrome.

**قبل البدء:** حمّل `window-calc-android.zip` من المحادثة، وافتح تطبيق «الملفات» واضغط على الملف ثم «استخراج» حتى يظهر مجلد فيه 6 ملفات: `index.html`، `package.json`، `capacitor.config.json`، `icon-only.png`، `icon-foreground.png`، `icon-background.png`. وحمّل أيضاً الملف `build-apk.yml` المرسل منفصلاً في المحادثة.

1. **حساب GitHub:** افتح github.com وأنشئ حساباً مجانياً (بريد وكلمة مرور)، وأكّد البريد من الرسالة.
2. **مستودع جديد:** اضغط ＋ ثم New repository. اكتب اسماً بالإنجليزية مثل `window-calc`، واختر **Public**، وفعّل Add a README file، ثم Create repository.
3. **وضع الكمبيوتر:** من قائمة ⋮ في Chrome فعّل «موقع سطح المكتب» حتى تظهر الأزرار كاملة.
4. **رفع الملفات الستة:** Add file ثم Upload files، واختر الملفات الستة من الجوال، وانتظر اكتمال الرفع ثم Commit changes.
5. **إنشاء ملف البناء:** Add file ثم Create new file. في خانة الاسم اكتب بالضبط `.github/workflows/build-apk.yml` (كتابة / تنشئ المجلدات تلقائياً). افتح ملف `build-apk.yml` على جوالك والصق كل محتواه في المربع الكبير (أو انسخه من الأسفل)، ثم Commit changes.
6. **تشغيل البناء:** افتح تبويب **Actions**. إن ظهر زر أخضر «I understand my workflows, go ahead and enable them» فاضغطه. سيبدأ البناء وحده. إن لم يبدأ فاختر Build APK ثم Run workflow.
7. **الانتظار:** من 5 إلى 10 دقائق. العلامة الخضراء ✓ تعني النجاح، والحمراء ✗ تعني خطأ (انظر الأسفل).
8. **تنزيل APK:** ارجع للصفحة الرئيسية للمستودع، واضغط **Releases** على الجانب الأيمن (أو افتح `github.com/اسمك/window-calc/releases`)، ثم في آخر إصدار حمّل `app-debug.apk` من قسم Assets.
9. **التثبيت:** افتح الملف المحمّل. عند ظهور «التثبيت من مصادر غير معروفة» اسمح لتطبيق Chrome، ثم ثبّت. وإن ظهر تحذير Play Protect فاختر «مزيد من التفاصيل» ثم «التثبيت على أي حال».

**إن ظهر ✗ أحمر:** افتح التشغيل الفاشل ثم الخطوة التي بجانبها علامة ✗، وانسخ آخر 20 سطراً من الخطأ وأرسلها لـ Claude ليصلح الوصفة. هذه الوصفة لم تُجرَّب فعلياً بعد، فقد يلزم تعديل بسيط في أول مرة.

**لتحديث التطبيق لاحقاً:** افتح `index.html` في المستودع، اضغط ✎ (تعديل)، واستبدل المحتوى بالجديد، ثم Commit. يبدأ البناء وحده وتنزّل نسخة جديدة من Releases.

نسخة debug صالحة للاستخدام الشخصي فقط، وليست للنشر في Google Play (يلزمها توقيع release).

### محتوى ملف `.github/workflows/build-apk.yml`
```yaml
name: Build APK
on:
  push:
    branches: [main, master]
  workflow_dispatch:
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: 17
      - name: Prepare files
        run: |
          mkdir -p www assets
          cp index.html www/index.html
          cp icon-*.png assets/ || true
      - run: npm install
      - run: npx cap add android
      - name: Add save-to-Downloads plugin
        run: |
          D=android/app/src/main/java/com/windowcalc/app
          cat > $D/SaveFilePlugin.java <<'EOF'
          package com.windowcalc.app;

          import android.content.ContentResolver;
          import android.content.ContentValues;
          import android.content.Intent;
          import android.net.Uri;
          import android.os.Build;
          import android.provider.MediaStore;
          import android.util.Base64;
          import com.getcapacitor.JSObject;
          import com.getcapacitor.Plugin;
          import com.getcapacitor.PluginCall;
          import com.getcapacitor.PluginMethod;
          import com.getcapacitor.annotation.CapacitorPlugin;
          import java.io.OutputStream;

          @CapacitorPlugin(name = "SaveFile")
          public class SaveFilePlugin extends Plugin {
            @PluginMethod
            public void save(PluginCall call) {
              String name = call.getString("filename");
              String mime = call.getString("mime", "application/octet-stream");
              String data = call.getString("data");
              if (name == null || data == null) { call.reject("missing"); return; }
              if (Build.VERSION.SDK_INT < Build.VERSION_CODES.Q) { call.reject("old android"); return; }
              try {
                byte[] bytes = Base64.decode(data, Base64.DEFAULT);
                ContentResolver r = getContext().getContentResolver();
                ContentValues v = new ContentValues();
                v.put(MediaStore.MediaColumns.DISPLAY_NAME, name);
                v.put(MediaStore.MediaColumns.MIME_TYPE, mime);
                v.put(MediaStore.MediaColumns.RELATIVE_PATH, "Download/");
                Uri uri = r.insert(MediaStore.Downloads.EXTERNAL_CONTENT_URI, v);
                if (uri == null) { call.reject("insert failed"); return; }
                OutputStream os = r.openOutputStream(uri);
                os.write(bytes);
                os.close();
                JSObject ret = new JSObject();
                ret.put("uri", uri.toString());
                call.resolve(ret);
              } catch (Exception e) {
                call.reject(String.valueOf(e.getMessage()));
              }
            }

            @PluginMethod
            public void open(PluginCall call) {
              String u = call.getString("uri");
              String mime = call.getString("mime", "*/*");
              if (u == null) { call.reject("missing"); return; }
              try {
                Intent i = new Intent(Intent.ACTION_VIEW);
                i.setDataAndType(Uri.parse(u), mime);
                i.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION | Intent.FLAG_ACTIVITY_NEW_TASK);
                getContext().startActivity(i);
                call.resolve();
              } catch (Exception e) {
                call.reject(String.valueOf(e.getMessage()));
              }
            }
          }
          EOF
          cat > $D/MainActivity.java <<'EOF'
          package com.windowcalc.app;

          import android.os.Bundle;
          import com.getcapacitor.BridgeActivity;

          public class MainActivity extends BridgeActivity {
            @Override
            public void onCreate(Bundle savedInstanceState) {
              registerPlugin(SaveFilePlugin.class);
              super.onCreate(savedInstanceState);
            }
          }
          EOF
      - name: Generate app icon
        continue-on-error: true
        run: npm i --no-save @capacitor/assets && npx capacitor-assets generate --android
      - run: npx cap sync android
      - name: Build debug APK
        working-directory: android
        run: chmod +x gradlew && ./gradlew assembleDebug
      - uses: actions/upload-artifact@v4
        with:
          name: window-calc-apk
          path: android/app/build/outputs/apk/debug/app-debug.apk
      - uses: softprops/action-gh-release@v2
        with:
          tag_name: build-${{ github.run_number }}
          name: النسخة ${{ github.run_number }}
          files: android/app/build/outputs/apk/debug/app-debug.apk
```

## 8. ملاحظات وقيود معروفة
- **تحذير مهم للبيانات المحفوظة:** كل بناء على GitHub Actions يوقّع APK بمفتاح debug جديد، فقد يرفض أندرويد التثبيت فوق النسخة القديمة ويطلب حذفها أولاً، **وحذفها يمسح الأنواع والعلاقات المحفوظة**. الحل المقترح (لم يُنفَّذ): تثبيت keystore واحد في ملف البناء. قبل حذف النسخة القديمة يمكن تدوين العلاقات يدوياً.
- لم يُجرَّب بناء APK ولا التشغيل على جهاز أندرويد حقيقي، بما فيه الإضافات الجديدة (الاختبارات كانت في Chrome عبر Playwright).
- الترتيب بأزرار ▲ ▼ فقط؛ السحب والإفلات لم يُنقل.
- **التطبيقات المحوّلة من مواقع (مثل Html2app):** تمنع غالباً تنزيل الملفات المولَّدة. توجد لوحة «🆘 طرق بديلة». الحل الأضمن APK حقيقي (Capacitor) أو فتح الرابط في Chrome وإضافته للشاشة الرئيسية.
- **الحفظ في APK:** إضافة `SaveFilePlugin.java` تكتب الملف في التنزيلات عبر MediaStore (أندرويد 10+)، وإلا تُستخدم قائمة المشاركة. بعد الحفظ يظهر شريط «📂 فتح الملف». في النتائج زران «💾 حفظ إكسل» و«📤 مشاركة إكسل».
- الأنواع والخانات الجديدة تُنقل بين الأجهزة بالنسخة الاحتياطية (القسم 4ب)، وليس هناك مزامنة تلقائية.
- التطبيق نفسه لا يحتاج إنترنت؛ الخط من النظام (الواجهة الافتتاحية أيضاً بلا مكتبات أو صور خارجية).
- الواجهة الافتتاحية لم تُجرَّب على جهاز أندرويد حقيقي، ولم يُبنَ APK بها بعد.
