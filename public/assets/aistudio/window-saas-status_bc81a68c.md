## 2. ما تم بناؤه

### أ. حماية الحاسبة الحالية
- مرجع اختبار ثابت (Golden Snapshot) لمحرك الحساب: 448 حالة في `tests/golden/`.
- أي تعديل يغيّر نتائج المعادلات يفشل الاختبار فورًا.
- تم التحقق من أن النتائج تطابق المعادلات الموثقة في README.

### ب. نواة المنصة (`src/saas/domain/`)
- **الأدوار:** مالك، مدير، مشغّل، مشاهد. فقط المالك يدير الفوترة والأعضاء.
- **الباقات (`plans.ts`):** كتالوج قابل للتعديل بالكامل، يضم الاسم والسعر (نص) وعدد المشاريع (null = غير محدود) والتنزيل (نعم/لا) والتفعيل.
- **الاشتراك (`subscription.ts`):** تجربة 7 أيام تبدأ فقط بعد تأكيد وسيلة الدفع من المزود. الإلغاء أثناء التجربة يمنع أول خصم.

### ج. الخدمات (`src/saas/services/`)
- **عزل الورشات:** كل قراءة مرتبطة بمعرّف الورشة. غير العضو يحصل على نفس رسالة الرفض التي يحصل عليها العضو بلا صلاحية.
- **قيود الباقة على الخادم:** الحفظ يتحقق من عدد المشاريع، والتنزيل يتحقق من الباقة. لا تعتمد هذه القيود على الواجهة.
- **الحسابات (`accountService.ts`):** تسجيل، دخول بكلمة مرور مشفّرة (scrypt)، جلسات، تأكيد وسيلة الدفع (محاكاة)، تغيير الباقة (محاكاة بدون دفع)، إلغاء التجديد.
- **منطق الباقة الفعلية:** الباقة المختارة تسري فقط عند وجود وصول فعّال (تجربة أو اشتراك). بدون ذلك تعود الورشة للباقة الأساسية.
- **لوحة الإدارة (خدمات):** تعديل الباقات، تغيير باقة أي ورشة، تحريك الساعة للاختبار، تشغيل محاكاة التحصيل.

### د. التجربة المحلية (`src/saas/local/`)
- خادم بسيط على `127.0.0.1:3100` بلا أي مكتبات خارجية.
- واجهة العميل: تسجيل، جدول مقارنة الباقات، عداد المشاريع، الحاسبة، الحفظ، التنزيل، تغيير الباقة (محاكاة)، إلغاء التجديد.
- لوحة الإدارة على `/admin`: الباقات، الورشات، ساعة الاختبار، التحصيل.

### هـ. الاختبارات
- 25 اختبارًا للصلاحيات والعزل والباقات والاشتراك والحسابات، مع مرجع الحساب الثابت.
- الأمر: `npm test`.
- التحقق من الأنواع (TypeScript) لا يُظهر أخطاء في الكود الجديد.

## 3. تشغيل التجربة

```bash
npm install --legacy-peer-deps
npm run saas:local
```

- العميل: `http://127.0.0.1:3100`
- الإدارة: `http://127.0.0.1:3100/admin`
- حساب مدير: `admin@local.test` / `admin123`
- حساب تجريبي (باقة المتقدمة، في التجربة): `owner@local.test` / `demo1234`

## 4. الباقات الحالية (قابلة للتعديل من لوحة الإدارة)

| المعرّف | الاسم | المشاريع | التنزيل |
|---|---|---|---|
| basic | الأساسية | 10 | لا (أونلاين فقط) |
| standard | القياسية | 50 | نعم |
| pro | المتقدمة | 200 | نعم |
| business | الأعمال | غير محدود | نعم |

- الأسعار فارغة حتى تقررها، وتظهر «يُحدد لاحقًا».
- الحاسبة متاحة في كل الباقات دائمًا، ولا تُمنع.
- الأرقام اقتراحات للتجربة فقط.

## 5. قرارات مفتوحة (تنتظر قرارك أو حساباتك)

1. **الأسعار** لكل باقة، وهل سنعرض سعرًا شهريًا وسنويًا.
2. **عدد المشاريع** لكل باقة (الأرقام الحالية اقتراحات).
3. **مزود الدفع** المناسب للتاجر في الأردن، مع التأكد أنه يدعم: حفظ البطاقة قبل التجربة، والاشتراك المتكرر، وWebhooks، وإلغاء التجديد.
4. **قاعدة البيانات:** Firestore (إن بقيت على Firebase) أو PostgreSQL (إن احتجت تقارير معقدة). التوصية الواردة في الخطة: Firebase إن كان التطبيق مبنيًا عليه.
5. **تسجيل الدخول:** Firebase Authentication مقترح في الخطة.
6. **الاستضافة والدومين:** Cloud Run أو Firebase App Hosting، بعد معرفة إطار التطبيق.
7. **الفروق الإضافية** بين الباقات، إن أردت شيئًا غير المشاريع والتنزيل (مثل عدد المستخدمين أو الأنواع المخصصة أو التقارير).

## 6. ما ينقص قبل الإطلاق الحقيقي

- ربط قاعدة بيانات حقيقية بدل الذاكرة، مع قواعد عزل مثبتة بالاختبار.
- ربط تسجيل دخول حقيقي (البريد وكلمة المرور الحالية محلية فقط، وليست آمنة للإنتاج).
- ربط مزود الدفع فعليًا: صفحة دفع مستضافة، وWebhooks موقعة، ومعالجة مكررة (Idempotency)، وفشل الدفع وإعادة المحاولة.
- فرض الخصم الحقيقي بدل المحاكاة، وإلغاء الترقية الوهمية (في النسخة الحقيقية يُدفع الفرق أولًا).
- نسخ احتياطي وسجل تدقيق لعمليات الإدارة.
- الشروط وسياسة الخصوصية وسياسة الإلغاء والاسترداد (مطلوبة قبل أي مدفوعات حقيقية).
- استشارة محاسب أو مختص في تسجيل النشاط والضرائب والفواتير الإلكترونية في الأردن.
- حذف بيانات «الحساب التجريبي» وكلمات المرور المدمجة قبل أي نشر.

## 7. خطة المتابعة المقترحة

1. **تجربة محلية (الآن):** جرّب الباقات والتجربة والإدارة، وأبلغني بأي شيء يبدو غير منطقي أو غير واضح.
2. **تثبيت القرارات:** الأسعار، وعدد المشاريع، ومزود الدفع، وقاعدة البيانات.
3. **المرحلة 1:** إنشاء مشروع Firebase (أو البديل) وربط تسجيل الدخول وقاعدة البيانات، مع اختبارات العزل.
4. **المرحلة 2:** ربط مزود الدفع في بيئة الاختبار (Sandbox) ودورة كاملة: تجربة، تحصيل، إلغاء، فشل، استرداد.
5. **المرحلة 3:** لوحة إدارة حقيقية، ونشر في بيئة تجريبية محدودة، ثم الإنتاج.
